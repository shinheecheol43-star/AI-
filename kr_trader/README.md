# 균형형 국내 자동매매 (키움증권 REST API)

국내 대형주 40종목 + KODEX 200 · KODEX 인버스를 **일봉 종가 기준**으로 매매하는 프로그램.
이 폴더만 있으면 어느 윈도우 PC에서나 돌아간다 (다른 저장소·계정 필요 없음).

> 투자 손실 책임은 본인에게 있다. 아래 순서(DRY → 모의투자 → 소액 실전)를 꼭 지킬 것.

---

## 1. 무엇을 하나 (규칙 요약)

| 시장 상태 (KODEX 200, 전날 종가) | 하는 일 |
|---|---|
| **상승** (종가 > 50일선 > 200일선) | 주도 섹터 종목 20일 고점 돌파 매수 · 손절 ATR×2 · 추적손절 ATR×3 · 최대 60거래일 |
| **강한 상승** (상승 + ADX ≥ 25) | 위에 더해 **KODEX 200 을 계좌의 50%** 보유 (조건 끝나면 매도) |
| **박스** (나머지) | 60일 고점 돌파 매수 · 손절 ATR×3 · 추적손절 ATR×5 · 최대 60일 + KODEX 200 볼린저 하단 매수(20일선 회복 시 매도) |
| **하락** (종가 < 50일선 < 200일선) | 새 주식 매수 없음 · KODEX 200 하락 신호 때만 KODEX 인버스 소량 |

- 종목 고르기: 120일 수익률로 본 **주도 섹터 상위 3개** 안, 종목 120일 수익률 > KODEX 200, 돌파한 날 종가가 캔들 위쪽 25% 안
- 크기: 손절까지 잃는 돈 = 계좌의 1% (지수가 20일선 아래면 0.5%, 인버스 0.5%) · 주식+코어 최대 8자리 · 레버리지·미수 없음
- **수익실현 목표가는 없다.** 오르면 따라 올라가는 추적손절선에 걸리거나 60일이 되면 판다
- 평소 보유: 주식 0~2종목이 대부분 (평균 1.3종목), 42% 의 날은 주식이 없다

### 과거 검증 (이 프로그램 코드 그대로, 2012-01 ~ 2026-11, 1,000만원, 비용 포함)

| 항목 | 값 |
|---|---|
| 연수익 | **+10.6%** (1,000만원 → 약 4,489만원) |
| 최대 낙폭 (매일 평가 기준) | **−15.1%** (2026년 2~3월), 다른 해는 −4% ~ −10% |
| 손실 난 해 | 2014(−3%), 2018(−5%) |
| 주식 거래 | 196건 · 승률 42% (적게 잃고 크게 버는 구조) |

과거 성과가 미래를 보장하지 않는다. 특히 승률이 낮아서 **3~5번 연속 손절은 흔하다.**

## 2. 준비 (처음 한 번)

1. **파이썬 설치**: python.org → Python 3.11 이상 → 설치 첫 화면에서 **"Add python.exe to PATH" 체크**
2. 이 폴더를 원하는 곳에 둔다 (예: `C:\kr_trader`). 경로에 한글이 없으면 더 안전하다
3. `setup.bat` 더블클릭 → 필요한 것 설치 + `config.env` 생성
4. **키움 REST API 신청** (그 컴퓨터 사용자의 키움 계정으로)
   - 키움증권 계좌 (가능하면 **이 프로그램 전용 계좌**. 다른 종목과 섞이면 수량 맞추기가 꼬인다)
   - 키움 REST API 사이트(openapi.kiwoom.com) 로그인 → API 사용 신청
   - **모의투자** 신청 (상시 모의투자) → 모의투자용 앱키/시크릿키 발급
   - **허용 IP 등록**: 이 PC의 공인 IP 를 등록해야 접속된다
   - 실전용 앱키는 나중에 따로 발급
5. `config.env` 를 메모장으로 열어 채운다. **키는 이 파일에만** 넣고, 카톡·메일·채팅으로 보내지 말 것

---

## 3. 단계별 사용

### 1단계 · DRY (주문 없음, 1~2주)
`config.env` 에 `MODE=DRY`. 매일 **16시 이후** `run_daily.bat` 실행 → 가상 매매 기록.
과거 연습: `run_daily.bat --date 2026-11-13` (그날 종가 기준으로 무엇을 했을지)

### 2단계 · MOCK (키움 모의투자, 1~2개월)
1. `MODE=MOCK`, 모의투자 앱키 입력
2. `py -3 check_api.py` → 토큰·잔고·현재가·일봉이 다 나오는지 확인
3. DRY 때 생긴 `state.json` 은 다른 이름으로 옮긴다 (모드마다 기록을 따로)
4. `install_tasks.bat` → 작업 스케줄러 등록
   - 평일 **08:55** `watch_stops.bat` : 15:20 까지 30초마다 손절가 감시 → 닿으면 시장가 매도
   - 평일 **15:41** `run_daily.bat` : 오늘 종가로 판단 → **장마감 후 시간외 종가(15:40~16:00)** 주문
5. 그 시간에 PC 가 켜져 있어야 한다 (절전 끄기)
6. 모의투자 체결 결과가 `trades.csv`·로그와 맞는지 매일 확인

### 3단계 · REAL (소액부터)
`MODE=REAL`, 실전 앱키, `REAL_CONFIRM=YES`, `START_CAPITAL` 을 작게 (예: 300만원) 시작.
MOCK 의 `state.json` 은 옮겨 두고 새로 시작한다.

## 4. 파일

| 파일 | 내용 |
|---|---|
| `strategy.py` | 매매 규칙 전부 (실매매·검증이 같은 코드를 씀) |
| `run_daily.py` | 장 마감 후 하루 한 번: 추적손절 올리기 · 청산 · 신규 진입 |
| `watch_stops.py` | 장중 손절 감시 (MOCK·REAL) |
| `broker.py` | 키움 REST API 연결 (DRY 는 주문 안 냄) |
| `backtest.py` | 과거 검증: `py -3 backtest.py` (기간·금액: `py -3 backtest.py 2020-01-01 30000000`) |
| `check_api.py` | 키움 연결 점검 (주문 안 냄) |
| `config.env` | 설정·키 (직접 만듦, 절대 공유 금지) |
| `state.json` | 프로그램이 들고 있는 포지션·손절가·가상현금 (**지우거나 고치지 말 것**) |
| `trades.csv`, `logs/` | 매매 기록·실행 로그 |

데이터는 야후 파이낸스 일봉(무료)을 쓰고, MOCK·REAL 에서는 오늘 봉을 키움 값으로 덮어쓴다.

---

## 5. 꼭 지킬 것

- 프로그램이 산 종목을 **손으로 팔거나 더 사지 말 것.** 손으로 팔면 다음 실행 때 "계좌 수량이 기록보다 적음" 경고 후 기록을 줄인다
- `state.json` 이 프로그램의 기억이다. 백업은 좋지만 수정·삭제는 하지 말 것
- PC 를 며칠 끌 때는 키움 앱의 **자동감시(스탑로스) 주문**으로 각 종목 손절가(로그·`state.json` 의 `stop`)를 걸어 두면 안전하다
- 하루 두 번 돌지 않게 막혀 있다. `--force` 는 주문이 두 번 나갈 수 있으니 상황을 알 때만
- 세금: 국내 주식·주식형 ETF 매매차익은 개인 비과세(거래세·수수료는 비용 0.15% 가정에 포함), **KODEX 인버스 차익은 배당소득세 15.4%**

## 6. 문제 해결

| 증상 | 확인 |
|---|---|
| 토큰 발급 실패 | 앱키/시크릿키 오타, 모의용 키를 REAL 에 넣었는지, **허용 IP 등록** |
| `kt10000 실패` · 매매구분 오류 | 모의투자가 시간외 종가(81)를 안 받을 수 있다 → 로그를 보관하고 설정 변경 문의 |
| 응답 이름이 달라 잔고가 0 | 키움 문서의 응답 필드명과 `broker.py` 의 이름(`ord_alow_amt`, `rmnd_qty` 등) 비교 |
| "오늘 봉이 없습니다" | 휴장일이거나 데이터가 아직 안 옴 → 아무것도 안 하고 끝남 (정상) |
| "장 마감 뒤에 실행하세요" | 15:31 이전 실행 방지 |
| 한글 깨짐 | `.bat` 으로 실행 (UTF-8 설정 포함) |

키움 API 의 api-id·주소·필드명은 `broker.py` 맨 위 `API` 표에 모여 있다. 키움 문서와 다르면 그곳만 고치면 된다.
